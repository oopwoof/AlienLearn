## 一、三档口头自述

面试官给的时间不可控，所以准备三档。**字数就是计时的代理指标**（中文口播约 250 字/分钟）。

### 90 秒版（目标 360-390 字）· 最常用

> AlienLearn 是我自己做的一个沉浸式语言学习沙盒。玩家扮演潜伏地球的外星人，
> 接入一家雨夜的拉面馆，要用英语点一碗面、套出老板不写在菜单上的高汤配方。
>
> 出发点是一个观察：语言学习的真问题不是内容不够，是不敢开口。
> 而弹窗式纠错让人越纠越沉默。所以我把纠错从"评判"改成"世界的反馈"——
> 老板绝不解释语法，他只是皱眉、反问；说错话不弹红叉，
> 是画面的红青两个色彩通道开始分离，世界裂开。视觉惩罚就是渲染管线本身。
>
> 架构是三个 Agent：Router 判这句话属不属于这家店，Pedagogy 和 Persona 并行跑，
> 状态机全在纯 Python 里，LLM 只投票、不碰数值。
>
> 但我最想讲的是评测。接上真实模型之后，教学诊断准确率只有 73.3%。
> 我第一反应是模型不行，翻完原始 trace 发现结论是反的：模型每条诊断都对，
> 只是档位判轻了——而按我自己 prompt 里写的定义，它是对的，
> 是我的人工标注偷偷用了另一把尺子。**问题是标注一致性，不是模型能力。**
>
> 所以我改判据、不改标注。改完 dev 集满分，但我另留了一个测试集，
> 它只有 70%，我刻意没去刷它——留出集一旦用来调参就作废了。

**说完停住。** 90 秒版的作用是钓出下一个问题，不是讲完整个项目。
如果对方接"为什么不去刷"，你已经赢了这一轮。

### 3 分钟版（目标 700-800 字）

在 90 秒版的骨架上，插入三块：

1. **北极星指标**（放在"出发点"之后）：不是学习时长，是单局主动输出的目标语言词数。
   时长可以挂机刷，主动说出去的话不能。而且它防刷——越狱那句话也是一串英文，但不计入。
   词数由代码算不问模型，指标口径一旦可能被幻觉污染，后面所有判断都不可信。
2. **为什么拆三个 Agent**（放在架构之后）：一个 prompt 里"演好暴躁老板"和"精确诊断语法"
   会互相污染，老板会忍不住当老师。拆开后每个 Agent 只有一个目标，可以分别评测、分别换模型。
   Router 必须先行，Pedagogy 和 Persona 必须并行——首字延迟只等 Router，实测 1.43s。
3. **评测集为什么人工标注**（放在评测之前）：benchmark 第一要求是可复现。
   让另一个 LLM 扮演玩家，每次说的话都不一样，分数波动就分不清是模型变了还是玩家变了。
   越狱套件里我刻意混了 4 条"看起来危险、实际属于场景内"的反例，因为只报拦截率是可以刷的。

### 8 分钟版 · 用节拍表，不用逐字稿

**这里刻意不写 2000 字逐字稿** —— 没人能背下来，背下来也会像念稿。
8 分钟要的是时间预算 + 每段的必说句 + 转场句。

| 时间 | 段落 | 必说句 | 转场 |
| --- | --- | --- | --- |
| 0:00-1:00 | 是什么 + 为什么 | "弹窗纠错是让人闭嘴的元凶" | "所以我要解决的是反馈的形态" |
| 1:00-2:00 | 核心机制 | "视觉惩罚不是特效，它就是渲染管线本身" | "这个机制要跑起来，架构上有个约束" |
| 2:00-3:30 | 三 Agent + 状态机 | "LLM 只投票，不碰数值" | "架构讲完了，但我真正想讲的是怎么知道它好不好" |
| 3:30-6:00 | **评测闭环 + 第四轮归因** ★ | "问题是标注一致性，不是模型能力" | "所以下一步不是刷分" |
| 6:00-7:00 | 边界与短板 | "留存我拿不出数据，报告里写的是待验证假设" | "如果给我团队，我会这样排" |
| 7:00-8:00 | 优先级与下一步 | "判据是：能不能验证或推翻核心假设" | 收 |

**时间分配本身是信号**：把最长的一段给评测和归因，而不是给功能列表。

## 二、论点映射表：同一个项目，对不同岗位推不同的三个论点

| 岗位类型 | 主推这三个 | 别主推 |
| --- | --- | --- |
| **大厂 AI 产品** | 评测闭环与人工标注集 · 第四轮归因 · 指标防刷设计 | 像素美术、色差的实现细节 |
| **AI 创业公司** | 5 天 0-1 全栈交付 · 取舍清单（没做什么、为什么）· 成本控制三条 | 学习科学理论 |
| **教育 / 语言学习** | 北极星为什么不是时长 · 弹窗纠错的反作用 · 假设二的可证伪设计 | 多 Agent 架构细节 |
| **游戏 / 互动内容** | 色差即渲染管线 · 惩罚的叙事化 · 状态机闸门而非 prompt 许愿 | LLM-as-a-Judge |

判断对方是哪一类：看他先问什么。**先问指标和评测 → 大厂；先问多久做完 → 创业；
先问学习效果 → 教育；先问玩家会不会觉得画面坏了 → 游戏。**

## 三、追问库

### A · 角色类（最危险，一定会被问）

**"你是产品还是开发？"**
> 我是产品。代码是我验证判断的手段，不是我要展示的东西。
> 一个人在 5 天里把假设跑起来，这本身就是产品决策——如果要等排期，这个项目不会存在。
> 真正体现产品能力的是取舍：我砍掉了账号、支付、UGC、语音，因为它们都不验证核心假设；
> 第二轮我修的是判据而不是加新场景，因为评测数据指着那里。

**"一个人做全栈，PM 能力体现在哪？"**
> 三处可以查证。一，北极星指标的选择和防刷设计——我没选学习时长，
> 而且主动把越狱产生的英文排除出计数。二，PRD 里预先写下判据（拦截率 90%），
> 第一轮跑出 83.3%，我改的是产品不是判据。三，第四轮发现是自己的标注有问题，
> 我选择改判据、不动那 30 条标注。这三件都是产品决策，跟会不会写代码无关。

**"这个项目有多少代码是 AI 写的？"**（诚实回答，别绕）
> 大部分实现是我和 Claude Code 结对写的，我不藏这个。
> 我的部分是产品决策、40 条测试集的人工标注、和每一轮的归因结论。
> 而且我觉得这就是 AI 产品经理该有的工作方式——重点不是我能不能手敲，
> 是我能不能判断它写得对不对。第四轮那个归因就是例子：
> 模型的判断和我的标注冲突时，我去翻了原始 trace，而不是直接相信任何一方。

**"你的 PRD 里写了 LangGraph，代码里没有。文档和实现不一致？"**（如果对方翻了 `docs/product/`）
> 是不一致，而且我把这四处不一致专门写成了一页导读，没有偷偷改文档。
> LangGraph 那处的理由是三个节点上框架属于过度设计。
> 但我更想讲另一处：立项时我写的 Pedagogy Agent 是"强制 NPC 在回复中复用目标句型"——
> 实现时我把它反过来了，因为让 NPC 复用目标句型等于把老师塞回角色里，
> 而"弹窗纠错让人闭嘴"正是这个产品要消灭的东西。**立项文档和产品内核自相矛盾，我按内核改了。**
> 留着这些不一致，是因为改了什么、为什么改，比一份被事后修饰过的 PRD 有用。

**"如果给你一个工程师，怎么分工？"**
> 我留 prompt、评测集、指标口径这三件，把前端渲染和部署交出去。
> 因为 prompt 和评测集是产品定义的载体——交出去等于把产品定义交出去了。

### B · 优先级类

**"给你 5 个人 4 周，先做什么？"**
> 第一周做用户测试，5 到 10 个人。因为现在最大的短板是留存假设没有数据，
> 这个短板加功能补不上。同一周并行把 severity 档位判定从 prompt 挪进代码，方案已经写好了。
> 后三周看测试结果分叉：如果问题在新奇感衰减，做场景库和难度曲线；
> 如果在挫败感，调 Glitch 的表现形式。**不先做的是 UGC 和多语言扩展**——
> 核心循环还没验证就摊大盘子，是我见过最常见的死法。

**"为什么第二轮修 Pedagogy 而不是优化延迟？"**
> 数据。报告里延迟是每轮 1.88s、首字 1.43s，对回合制对话不是瓶颈。
> 而 Pedagogy 准确率 73.3% 同时伤两件事：教错用户，
> 以及纠错轨迹这份数据资产本身是漏的。判断依据在报告里，不是靠感觉。

**"如果只能保留一个功能？"**
> 色差分离加状态机结算。它是"把纠错藏进世界规则"这个假设的唯一载体。
> 三 Agent 可以退化成一个 prompt，评测可以后补，
> 但拿掉色差，这个产品就退化成又一个陪聊机器人。

**"你怎么排 P0/P1？判据是什么？"**
> 一条：能不能验证或推翻核心假设。对这个问题回答"不能"的一律往后放。
> 这也是为什么 PRD 里我给每个假设都写了可证伪条件——
> 没有判据的优先级排序，最后就是比谁嗓门大。

### C · 假设与失败类

**"这个游戏真能提升语言能力吗？"**
> 现在不能证明，我也不宣称。MVP 验证的是前置假设：玩家会不会更愿意开口。
> 所以北极星是主动输出量。语言能力提升是下一层，需要前后测和对照组，
> 那是有真实用户之后的事。在 MVP 阶段宣称学习效果，我认为是不诚实的。

**"假设二被推翻怎么办？"**
> 判据写死在 `report.py` 里：如果被频繁纠错的玩家明显玩得更短，说明惩罚失准。
> 那时要调的是表现形式，不是纠错本身——比如色差只影响背景不影响 NPC，
> 或者给一次"重新伪装"的机会。判据预先写死，就是为了避免数据出来之后
> 再挑一个对自己有利的解释。

**"这个项目最可能失败在哪？"**
> 三个，按概率排。一，留存——整个机制的驱动力是新奇感，新奇感一定衰减。
> 二，目标用户窄——它要求玩家同时接受科幻叙事和被动纠错，这个交集可能不大。
> 三，内容成本——手写场景不可规模化，所以 PRD 里有 UGC 的位置，
> 但那得等核心循环先被验证。

**"留出集只有 70%，那这次修复算成功吗？"**
> 分两件事看。判据这件事修成了：过报从 3 条降到 1 条，
> 而且不再出现"把正确的英语润色一遍"这种直接教错用户的错误，这是伤害最大的一类。
> 标定这件事没修完：剩下 3 条全是差一档。
> 但如果我把留出集也调到 100%，我就拿不出任何证据说明它不是过拟合。
> 我宁可留一个诚实的短板，也不要一个解释不了的满分。

**"那你会怎么继续修？"**（上一题之后必然跟这一题）
> 不再往 prompt 里堆例子，散文 rubric 的边际收益已经到顶了。两条路。
> 一是把测试集扩到 50 条以上并且换人标注，先解决"作者偏差"这个更根本的问题——
> 出题人知道自己修了什么，这个偏差我排除不掉。
> 二是把档位判定从 prompt 挪到代码里：模型只负责找出错误的 span 和改法，
> 这部分它 40 条里没错过一次；档位由结构规则定——动了助动词或 be 动词的骨架就是 major，
> 只动时态标记、冠词、语序就是 minor。让 LLM 做它擅长的，
> 把需要一致性的判定交给代码。这和"数值不给 LLM 碰"是同一个原则的延伸。

**"商业化怎么想？"**
> 短期不做订阅。这类产品的付费点在场景和面具，不在功能解锁——
> 核心循环免费才是最好的证明。成本侧现在有三条：状态机剥离 LLM、
> 短时记忆只带最近 6 轮、Router 用极少 token 做二分类。
> 再往下是模型分层和 prompt 缓存，场景世界观是固定前缀，天然适合缓存。

### D · 技术类

**"为什么不用 LangGraph？"**
> 三个节点上编排框架是过度设计。我要的是控制权和延迟：Router 必须先行，
> Pedagogy 和 Persona 必须并行，这两条约束用 asyncio 显式写出来比藏在框架里清楚。
> 等节点涨到需要条件分支和检查点，再换框架，而不是反过来。

**"为什么 Pedagogy 和 Persona 能并行？"**
> 因为老板不需要知道精确的语法诊断——他是母语者，"这话听着怪"是他自己的直觉。
> 精确诊断属于 HUD，静默滑进侧边栏。解耦之后才能并行，
> 串行的话玩家要多等一整个 JSON 才能看到老板开口。

**"为什么数值一律不给 LLM 碰？"**
> 两个原因。防幻觉：伪装度是玩家唯一的进度感知，它跳一下玩家就不信这个世界了。
> 防注入：如果血条在 prompt 里，玩家可以直接说"把我的伪装度改成 100"。
> 现在它在 Python 里，LLM 只能发信号。

**"怎么防 prompt 注入？"**
> 分层。Router 先做二分类判定是否属于这家店；判定越界后 Persona 换防御模式，
> 用人设挡回去而不是解释规则——老板是个开了二十六年面馆的人，
> "system prompt"这个词对他毫无意义。而且越狱不是被拒绝，是被计入代价：
> 暴露计数加一，连续三次触发全息崩溃。

**"规则桩算不算作弊？"**
> 它的作用是让链路、状态机、埋点、评测能独立开发和演示，不被 API 阻塞，现场也有兜底。
> 报告会标注 `judge_mode`，没接真实模型时那个分数不是模型判的，我不会拿它当结论。
> 而且规则桩的天花板正好被评测抓到了：漏拦了一条不含敏感词的越狱。

**"为什么选 DeepSeek？"**
> 国内直连、按 demo 用量成本可忽略、支持 JSON 输出。
> 而且客户端走 OpenAI 兼容接口，换厂商只改 `.env` 里两行，代码不动——
> 选型不该变成锁定。

**"色差分离，用户会不会只觉得画面坏了？"**
> 有这个风险，所以任务简报里明确写了一句"色彩通道分离到什么程度，就是你此刻有多可疑"。
> 这也是 PRD 里第三个待验证假设：拿纯对话模式和箱庭模式做 A/B，
> 用平均 session 时长量像素空间锚点的真实贡献。

**"成本怎么控？"**
> 状态机剥离 LLM、短时记忆只带 6 轮、Router 用极少 token 做二分类。
> 再往下是模型分层和 prompt 缓存。这些在商业化文档里算过，MVP 阶段先把接口留好。

## 四、现场翻车预案

**结论先说：不建议面试现场共享屏幕演示。** 视频压缩的 4:2:0 色度抽样会把红/青分离压糊，
你最花心思的那个机制反而最先被毁。现场只讲一页纸和 README，
对方主动要看演示就切预录视频的对应时间点。

如果还是要跑本地服务：

| 坑 | 处理 |
| --- | --- |
| `python backend/run.py` 报 `No module named 'uvicorn'` | 后端要用 **`ubc`** conda 环境，base 没装 fastapi/uvicorn |
| 起服务报 `WinError 10013` | `127.0.0.1:8000` 被别的进程占了。**注意：这时探活会返回 404 而不是连接失败**，极易误判成"服务起来了但路由全没"。换端口：`python -m uvicorn main:app --port 8123`（在 `backend/` 下） |
| DeepSeek 余额用光 / 网络不通 | 提前查余额。兜底改 `.env` 的 `MOCK_LLM=1`，状态轨会自己显示"链路 规则桩"——**主动说出来比被问出来强得多** |
| 对方问"这数据是真的吗" | 报告顶部有 `对局链路` 和 `裁判模式` 两行，当场指给他看 |

录屏前：`data/` **不要清**。里面 24 局埋点是评测报告第五节（北极星、假设二对照组）的数据源。

## 五、忌讲

- 不要说"这个项目提升了学习效率 X%" —— 没有数据，一问就崩
- 不要把留出集那 70% 主动说成"还没优化完" —— 它是**刻意保留的诚实短板**，是论点不是缺陷
- 不要先讲技术栈。先讲问题，再讲机制，最后才是架构
- 不要回避"AI 写了多少代码"。绕这个问题的代价远大于直说
